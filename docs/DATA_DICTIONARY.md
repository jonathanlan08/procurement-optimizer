# Data dictionary

Every table in the v0.1.0 schema (40 tables, migrations `0001`-`0015`), with column types
and purpose. Generated by reading `backend/src/app/models/*.py` and
`backend/migrations/versions/*.py`.

Conventions that apply to almost every table and are not repeated per row:

- `id` - `UUID`, primary key, application-generated.
- `organization_id` - `UUID NOT NULL`, FK to `organizations.id` (`RESTRICT`), plus
  `UNIQUE (organization_id, id)` so children can point composite FKs at it.
- `created_at` / `updated_at` - `TIMESTAMPTZ`, UTC.
- `version` - `INTEGER`, optimistic locking (`If-Match`).
- `archived_at` / `archived_by_id` / `archive_reason` - soft delete.
- **Composite FK** below means `(organization_id, <col>) → <parent>(organization_id, id)`.

See [DATABASE.md](DATABASE.md) for conventions and the migration inventory.

| `state` | `report_state_enum NOT NULL` | `pending` \| `ready` \| `failed` |
| `generated_by_id`, `generated_at` | | Indexed `(organization_id, generated_at DESC)` as `ix_reports_org_time` |
| `expires_at` | `TIMESTAMPTZ NOT NULL` | Retention marker; `REPORT_RETENTION_DAYS = 90` is a documented assumption, not a spec requirement |
| `purged_at` | `TIMESTAMPTZ` | ERD §11 purge marker |
| `error_message` | `TEXT` | Set only when `state = failed` |

No `updated_at` / `version` / `archived_at`: a report row is written once and only ever
mutated by a purge.
